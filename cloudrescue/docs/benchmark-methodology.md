# Benchmark methodology

Run `uv run python -m backend.benchmark --seed 42 --output benchmark-output`. JSON includes the model version, environment, configuration, seed, policy parameter versions, generated workload frames, tuning scores, per-policy measurements, and held-out aggregates. CSV provides one row per workload/policy pair with a JSON time series column.

Ten equally weighted workload families each contain 12 development, six validation, and six held-out traces. SHA-256 derives each seed from the model version, master seed, partition, family, and index. Tuning rejects held-out data. The fixed search scores 11 configurations on development request success, then selects from the top three using validation success. All variants use identical traces and common per-request random streams within each workload.

The model simulates 36 one-second steps, a primary and a standby, shared dependencies, bounded service capacity, and request deadlines. The latency family can breach deadlines without losing instance health. Independent service failures supply diagnostic evidence for Storage alongside Messaging. The benchmark reports only modeled Messaging request outcomes. Recovery and delay metrics use the first detected episode. See the Phase 3 benchmark definitions for request success, impairment, and overhead.

A positive detection label requires three consecutive seconds of exogenous primary impairment under the configured health, latency, capacity, or transient probability criteria. False-positive and false-negative rates condition on negative and positive workload labels respectively. These are workload-level detection measures. A policy that successfully masks impairment can produce a false negative under this definition. The rates do not measure diagnostic root-cause accuracy.

Results report mean, median, 5th and 95th percentiles, and 95% percentile bootstrap intervals using 600 family-stratified resamples. Paired comparisons bootstrap policy-minus-baseline success differences within the same workload. Harm is the proportion of trials with lower request success than baseline. Conditional delay metrics include only workloads that produced the event. The intervals reflect simulated workload variation and are not simultaneous or multiplicity-adjusted. Partition separation protects the tuning procedure from direct test input. The public deterministic generator is not a blind external validation set.
