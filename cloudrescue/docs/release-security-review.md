# Release security review

The review covered tracked filenames, source and local configuration, commit history, simulator target selection, authentication, and package metadata. Targeted history checks found no matches for common hosted Git, cloud access-key, and private-key patterns. The committed .env files are examples. The database passwords shown in examples and CI are local or disposable defaults. Replace those defaults before any shared use. Keep local databases, session data, audit exports, logs, and generated benchmark files outside Git. The checks are heuristic and cannot rule out an arbitrary unrecognized credential.

Application endpoints are intended for loopback. The measurement runner accepts no target URL, opens its own listener, disables proxies and redirects, and uses the existing simulator handler. The recovery API uses named accounts and fixed typed actions. Legacy shared-token access ends when the first account exists. Audit downloads can contain operator attribution and should be handled as local sensitive data.

MIT remains appropriate for original CloudRescue and trace-package code. All 536 npm lockfile entries declare a license. Installed Python metadata provides license information for 39 distributions, with classifier fallbacks for colorama and pathspec. Items to verify against the actual distribution include Sharp's platform-specific libvips bundles (LGPL), psycopg and psycopg-binary (LGPL), and certifi (MPL). The build and test tree also includes MPL-licensed lightningcss and axe-core. Review the files actually shipped on each platform and preserve applicable licenses, notices, and source availability before public distribution.

The November 14 npm audit reported seven moderate entries from one [minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249) and its six development lint dependents. The production-only npm audit returned zero findings. The previous locked Python runtime audit found no known vulnerabilities. Keep the current lockfile for private review with lint scoped to trusted project configuration. Before public release, resolve the advisory with a compatible lint-chain update and rerun lint, tests, build, and both audits. The hosted push and pull-request workflows passed with disposable PostgreSQL and loopback simulator verification.
